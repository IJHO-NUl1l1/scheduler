# 토큰 사용량 줄이기

앱 내장 채팅은 사용자의 Claude Code 구독으로 돌아간다(PLAN.md 10장). 구독에는 5시간·주간 사용 한도가 있어서, 같은 일을 더 적은 토큰으로 하는 게 곧 더 오래 쓰는 방법이다.

## 1. 토큰이 어디서 나가나

요청 한 번 = (시스템 프롬프트 + 도구 정의 + 대화 기록 + 이번 메시지)를 **왕복마다** 다시 보낸다.
도구를 3번 부르면 이 묶음을 3~4번 보낸다. 그래서 줄일 곳은 다섯 군데다.

| 줄일 곳 | 내용 |
|---|---|
| 고정 머리 | 시스템 프롬프트 + 도구 정의. 매 왕복마다 붙음 |
| 왕복 수 | 도구 호출 1번 = 머리부터 다시 1번 |
| 대화 기록 | 이어지는 대화는 이전 내용 전부를 다시 보냄 |
| 출력 | 답 길이, 생각(thinking) 양 |
| 호출 자체 | AI가 필요 없는 일에 AI를 부르는 것 |

## 2. 대표적인 방법과 우리 적용

| # | 방법 | 원리 | 우리 프로젝트 적용 | 상태 |
|---|---|---|---|---|
| 1 | **시스템 프롬프트 최소화** | 기본 Claude Code 프롬프트는 코딩용이라 약 2.7만 토큰 | `--system-prompt`로 10줄짜리 플래너 전용 프롬프트로 교체 (`apps/desktop/src/main/claude.ts`) | 적용 |
| 2 | **안 쓰는 도구·설정 끄기** | 도구 정의도 매번 보내짐 | `--tools ""`(내장 도구 끔), `--disable-slash-commands`, `--setting-sources ""`, `--strict-mcp-config` → planner 도구만 남김 | 적용 |
| 3 | **프롬프트 캐시 유지** | 앞부분이 글자 하나까지 같으면 캐시에서 읽음 (API 요금 기준 일반 입력의 10%) | 시스템 프롬프트에 날짜·상태 같은 바뀌는 값을 넣지 않음. 모드가 달라도 같은 프롬프트 사용. 바뀌는 정보는 메시지 쪽에 | 적용 |
| 4 | **필요한 정보 미리 넣기** | Claude가 조회하러 가는 왕복 1번 = 머리 전체 1번 | 앱이 오늘 상황(`renderToday`)을 메시지 앞에 넣어줌. 볼트가 바뀌었을 때만 다시 넣음 | 적용 |
| 5 | **여러 개는 한 번에** | 할 일 5개를 add_task 5번 = 왕복 5번 | MCP에 `add_tasks`(일괄 추가) 추가, 프롬프트로 사용 지시 | 적용 |
| 6 | **재확인 금지** | 수정 후 "잘 됐나" 재조회가 왕복을 늘림 | 프롬프트: "수정한 뒤 확인용 재조회 하지 않는다" | 적용 |
| 7 | **도구 결과 압축** | 도구가 돌려준 텍스트도 다음 왕복부터 계속 보내짐 | MCP 출력은 JSON 대신 한 줄 요약 텍스트(`render.ts`) | 적용 |
| 8 | **대화 길이 제한** | 이어지는 대화는 기록이 계속 쌓임 | 8턴 넘거나 30분 쉬면 새 대화. 상태는 다시 넣어주므로 맥락 손실이 적음. "새 대화" 버튼 | 적용 |
| 9 | **모델·생각량 고르기** | 큰 모델·깊은 생각은 비쌈 | 빠른 모드: sonnet + effort low / 계획 모드: opus + effort high. 사용자가 고름 | 적용 |
| 10 | **답 짧게** | 출력 토큰은 입력보다 비쌈 | 프롬프트: "한 일과 결과만, 인사·반복 없이" | 적용 |
| 11 | **AI 안 써도 되는 건 앱이** | 가장 확실한 절약은 안 부르는 것 | 빠른 추가 파서(`parseQuickAdd`: "내일 3시 회의 @"), 체크·옮기기·시간 빼기·삭제는 버튼. AI는 정리·계획에만 | 적용 |
| 12 | **사용량 보이기** | 보이면 조절할 수 있음 | 답마다 모델·왕복·입력(캐시)·출력 표시, 하단에 대화 턴·오늘 합계. `usage.jsonl`에 기록 | 적용 |
| 13 | 도구 수 줄이기 | 도구 정의 약 4천 토큰(18개) | 모드별로 노출 도구를 나누는 방법. 캐시 읽기라 효과가 작아서 보류 | 보류 |
| 14 | 5시간 한도 표시 | stream-json의 `rate_limit_event`에 한도 상태가 옴 | 채팅 패널에 "한도 정상 / 리셋 시각" 표시 | 다음 |

## 3. 측정 결과 (2026-11-25)

같은 요청 "오후 3~4시 '공모사업 서류 검토' 추가하고 오늘 두 줄 요약"을 조합별로 실행.

| 조합 | 모델 | 왕복 | 입력 합계 | 그중 캐시 읽기 | 출력 |
|---|---|---|---|---|---|
| 기본 Claude Code | opus-5 | 4 | 105,647 | 78,749 | 498 |
| 1·2번 적용 | opus-5 | 3 | 9,557 | 4,535 | 312 |
| 1·2번 적용 | sonnet-5 | 3 | 9,760 | 4,619 | 364 |
| 1·2번 적용 | haiku-4.5 | 3 | 12,449 | 5,876 | 843 |
| 1·2·4번 적용 | sonnet-5 | **2** | 9,912 | 8,924 | 290 |

- 1·2번만으로 입력이 **약 91% 감소**.
- 4번(미리 넣기)으로 왕복 3 → 2. 새로 쓴 캐시가 984토큰뿐이고 나머지는 캐시 읽기.
- haiku는 답을 길게 써서 오히려 손해. 그래서 빠른 모드도 sonnet + effort low로 둠.
- 앱 안 실제 요청("토너 주문 시간 잡고 학업계획서 이틀로 쪼개기", sonnet·low): 3왕복, 입력 12.4k(캐시 읽기 10.8k), 출력 355, 4.8초.
- 측정에 쓴 숫자는 Claude Code가 보고하는 값이다. 구독 한도가 토큰을 정확히 어떻게 세는지는 공개돼 있지 않다. API 요금 기준으로 캐시 읽기는 일반 입력의 10%다.

## 4. 지키는 규칙 (코드 수정 시)

- `SYSTEM_PROMPT`(claude.ts)에 날짜, 시각, 사용자 데이터 등 바뀌는 값을 넣지 않는다. 캐시가 깨진다.
- MCP 도구 설명을 자주 바꾸지 않는다. 바꾸면 그날 첫 요청은 캐시를 새로 쓴다.
- 새 기능이 AI 없이 될 수 있으면 앱 버튼·파서로 먼저 만든다.
- `--bare`는 쓰지 않는다. 구독 로그인을 안 읽어서 API 키가 필요해진다.
